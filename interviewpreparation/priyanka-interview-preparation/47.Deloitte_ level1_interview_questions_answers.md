## 1. How did you integrate an AI-platform-driven solution? Which platform did you use?

### Interview-ready answer

“In my project, the AI integration was done through an AI platform/API. The application sends the user input or business data to the AI service through a REST API. The AI service processes the request and returns a response, which is then validated and displayed in the application.

The integration normally includes:

1. Creating an API request from the backend.
2. Sending the prompt or input data to the AI platform.
3. Authenticating using an API key or secure token.
4. Handling the AI response and errors.
5. Applying validation, logging, and timeout handling.
6. Displaying the result in the frontend.

The exact platform should be mentioned honestly. Examples include Azure OpenAI, OpenAI API, Amazon Bedrock, Google Vertex AI, or an organization-specific AI platform.”

### Important

Do not claim that you used a platform unless you actually used it. You can say:

> “I worked on the integration layer and used REST APIs. The AI platform was [actual platform name].”

## 2. What is MongoDB Standalone?

A MongoDB standalone is a single MongoDB server instance that is not part of a replica set or sharded cluster.

### Characteristics

- Simple to configure.
- Suitable for local development and small applications.
- Does not provide automatic failover.
- If the server goes down, the database becomes unavailable.
- Not recommended for highly available production systems.

### MongoDB deployment types

| Type | Meaning |
|---|---|
| Standalone | One MongoDB server |
| Replica set | Multiple servers maintaining copies of data |
| Sharded cluster | Data distributed across multiple servers |

### Interview answer

“A MongoDB standalone is a single database instance. It is easy to set up, but it does not provide automatic failover or high availability. For production, a replica set is generally preferred.”

## 3. What is Kafka?

Apache Kafka is a distributed event-streaming platform used to publish, store, and consume messages or events.

### Main components

- **Producer:** Sends messages to Kafka.
- **Consumer:** Reads messages from Kafka.
- **Topic:** Logical category where messages are stored.
- **Partition:** Splits a topic for scalability and parallel processing.
- **Broker:** Kafka server that stores and serves messages.
- **Consumer group:** Group of consumers sharing the processing work.
- **Offset:** Position of a message within a partition.

### Example

When an order is created:

1. Order service publishes an `OrderCreated` event.
2. Kafka stores the event in an `orders` topic.
3. Payment service consumes the event.
4. Notification service also consumes the event.

### Why use Kafka?

- Asynchronous communication.
- Decouples microservices.
- High throughput.
- Fault tolerance.
- Event-driven architecture.
- Message replay using offsets.

### Kafka vs REST

| REST | Kafka |
|---|---|
| Synchronous request-response | Asynchronous event communication |
| Tight runtime dependency | Loose coupling |
| Client waits for response | Consumer processes later |
| Suitable for immediate queries | Suitable for events and streaming |

Common AWS services:

- **EC2:** Virtual server.

## 6. What is the use case of S3?

Amazon S3 is an object-storage service used to store files and unstructured data.

### Common use cases

- Storing images.
- Storing documents and PDFs.
- Uploading user files.
- Storing application logs.
- Backups.
- Static website hosting.
- Data lakes.
- Storing videos and reports.

### Example

In a document-management application:

1. User uploads a document.
2. Backend validates the file.
3. Backend uploads the file to S3.
4. S3 returns an object key or URL.
5. The application stores the key in the database.
6. The user downloads the document using a secure URL.

### Important point

Usually, the database stores file metadata, while S3 stores the actual file.

## 7. What is AWS Lambda?

AWS Lambda is a serverless compute service that runs code in response to events without requiring the developer to manage servers.

### Example triggers

- S3 file upload.
- API Gateway request.
- SQS message.
- Scheduled CloudWatch event.
- DynamoDB stream.

### Benefits

- No server management.
- Automatic scaling.
- Pay only for execution usage.
- Good for event-driven tasks.

### Limitations

- Execution time and resource limits.
- Cold-start latency may occur.
- Not ideal for long-running processes.
- Stateless execution model.

### Example

“When a file is uploaded to S3, a Lambda function can automatically resize the image, scan it, or process its metadata.”

# Java

## 8. What is a Lambda Expression?

A lambda expression is a concise way to represent an anonymous function in Java.

### Syntax

```java
(parameters) -> expression
```

or

```java
(parameters) -> {
    // statements
}
```

### Example

```java
(a, b) -> a + b
```

### Benefits

- Reduces boilerplate code.
- Used with functional interfaces.
- Commonly used in Streams API.
- Improves readability for simple operations.

---

## 9. What is a Functional Interface?

A functional interface is an interface that contains exactly one abstract method.

It can have:

- One abstract method.
- Any number of default methods.
- Any number of static methods.

### Example

```java
@FunctionalInterface
interface Calculator {
    int add(int a, int b);
}
```

Usage:

```java
Calculator c = (a, b) -> a + b;
```

### Common built-in functional interfaces

| Interface | Method | Purpose |
|---|---|---|
| Predicate<T> | boolean test(T t) | Checks a condition |
| Function<T, R> | R apply(T t) | Converts one value to another |
| Consumer<T> | void accept(T t) | Consumes a value |
| Supplier<T> | T get() | Supplies a value |

---

## 10. What is Predicate and why is it used?

`Predicate<T>` is a functional interface used to test a condition. It returns a boolean value.

### Method

```java
boolean test(T t);
```

### Example

```java
Predicate<Integer> isAdult = age -> age >= 18;
```

### Why use Predicate?

- Filtering data.
- Validating objects.
- Reusing conditions.
- Combining conditions using `and()`, `or()`, and `negate()`.

### Stream example

```java
List<Integer> result = numbers.stream()
        .filter(n -> n > 10)
        .toList();
```

The condition inside `filter()` behaves like a Predicate.

# JPA and Hibernate

## 11. JPA vs Hibernate

### JPA

JPA, or Java Persistence API, is a specification that defines how Java objects are mapped to relational database tables.

### Hibernate

Hibernate is an ORM framework and one of the most popular implementations of JPA.

### Comparison

| JPA | Hibernate |
|---|---|
| Specification | Implementation |
| Defines interfaces and rules | Provides actual functionality |
| Vendor-independent | Hibernate-specific features available |
| Uses annotations such as `@Entity` | Implements JPA behavior |

### Interview answer

“JPA is a specification for ORM, whereas Hibernate is an implementation of that specification. We can write code using JPA interfaces and annotations, while Hibernate performs the actual persistence operations.”

---

## 12. What happens if an entity table does not have a primary key?

JPA requires every entity to have an identifier.

An entity normally uses:

```java
@Id
```

If no identifier is defined, the application generally fails during startup or entity mapping validation.

### Important

A database table may technically exist without a primary key, but it cannot normally be mapped as a standard JPA entity without an identifier.

### Example

```java
@Entity
class Employee {

    @Id
    private Long id;
}
```

---

## 13. Is there any other key that can be used instead of a primary key?

JPA does not require the database column to be physically declared as a database primary key, but it requires an entity identifier that uniquely identifies each entity instance.

Possible options:

1. Use an existing unique column.
2. Use a composite key.
3. Use a generated surrogate key.
4. Map the table as a read-only query/view using a framework-specific approach.
5. Use a database view with a unique identifier.

### Important distinction

- **Database primary key:** Constraint defined in the database.
- **JPA identifier:** Field or fields used by JPA to identify an entity.

The JPA identifier must be unique and stable.

---

## 14. Can you create a primary key?

Yes, if database changes are allowed.

### SQL example

```sql
ALTER TABLE employee
ADD CONSTRAINT pk_employee PRIMARY KEY (employee_id);
```

If the column already exists, it must contain:

- No duplicate values.
- No NULL values.

---

## 15. What if you cannot add a new column?

You can use an existing unique column as the JPA identifier.

Example:

```java
@Entity
class Employee {

    @Id
    @Column(name = "employee_code")
    private String employeeCode;
}
```

This is valid only if `employee_code` is unique and never changes.

### If no single unique column exists

Use a composite key if a combination of existing columns uniquely identifies each row.

### Important warning

If the table has no unique combination of columns, standard JPA entity mapping is unsafe because Hibernate cannot reliably identify, update, or delete individual rows.

For read-only use cases, alternatives include:

- Native SQL queries.
- DTO projections.
- Spring Data JDBC.
- Database views.
- Read-only query mappings.

---

## 16. What is a Composite Key?

A composite key is a key made up of two or more columns.

The combination of columns uniquely identifies a row.

### Example

An enrollment table may use:

```text
student_id + course_id
```

A student can enroll in many courses, and a course can have many students. The combination identifies one enrollment.

### JPA example using `@EmbeddedId`

```java
@Embeddable
public class EnrollmentId implements Serializable {

    private Long studentId;
    private Long courseId;
}
```

```java
@Entity
public class Enrollment {

    @EmbeddedId
    private EnrollmentId id;
}
```

### Alternative

Use `@IdClass`.

### Interview answer

“A composite key is a primary key formed using multiple columns. In JPA, it can be mapped using `@EmbeddedId` or `@IdClass`.”

# Java Streams API

## 17. Find employees whose salary is greater than 20,000

### Employee class

```java
class Employee {
    private String name;
    private double salary;

    public Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }

    public String getName() {
        return name;
    }

    public double getSalary() {
        return salary;
    }
}
```

### Stream solution

```java
List<Employee> result = employees.stream()
        .filter(e -> e.getSalary() > 20000)
        .toList();
```

### Print the names

```java
employees.stream()
        .filter(e -> e.getSalary() > 20000)
        .map(Employee::getName)
        .forEach(System.out::println);
```

### Explanation

- `stream()` creates a stream.
- `filter()` selects employees with salary greater than 20,000.
- `map()` extracts employee names.
- `forEach()` prints the names.

## 18. Convert a List into a Map

Suppose we have:

```java
List<Employee> employees;
```

Convert it into a map where the key is employee ID and the value is employee object:

```java
Map<Long, Employee> employeeMap = employees.stream()
        .collect(Collectors.toMap(
                Employee::getId,
                Function.identity()
        ));
```

### If duplicate keys are possible

```java
Map<String, Employee> employeeMap = employees.stream()
        .collect(Collectors.toMap(
                Employee::getName,
                Function.identity(),
                (existing, replacement) -> existing
        ));
```

The merge function decides what to do when duplicate keys occur.

---

## 19. List contains duplicate names. How do you handle it?

The solution depends on the requirement.

### A. Get unique names

```java
List<String> uniqueNames = employees.stream()
        .map(Employee::getName)
        .distinct()
        .toList();
```

### B. Group employees by name

```java
Map<String, List<Employee>> grouped = employees.stream()
        .collect(Collectors.groupingBy(Employee::getName));
```

### C. Count occurrences of each name

```java
Map<String, Long> countByName = employees.stream()
        .collect(Collectors.groupingBy(
                Employee::getName,
                Collectors.counting()
        ));
```

### D. Convert to Map and keep the first duplicate

```java
Map<String, Employee> map = employees.stream()
        .collect(Collectors.toMap(
                Employee::getName,
                Function.identity(),
                (first, second) -> first
        ));
```

# Database

## 20. What is Indexing?

An index is a database data structure that improves the speed of data retrieval.

It works similarly to an index in a book: instead of scanning every row, the database can locate matching rows faster.

### Example

```sql
CREATE INDEX idx_employee_name
ON employee(name);
```

### Benefits

- Faster `SELECT` queries.
- Faster filtering.
- Faster joins.
- Faster sorting in some cases.

### Disadvantages

- Requires additional storage.
- Slows down `INSERT`, `UPDATE`, and `DELETE`.
- Too many indexes can reduce performance.

### Important

A primary key usually creates a unique index automatically, depending on the database system.

## 21. SQL vs MongoDB

| SQL Database | MongoDB |
|---|---|
| Relational database | Document database |
| Tables and rows | Collections and documents |
| Fixed or structured schema | Flexible schema |
| Uses SQL | Uses MongoDB query language |
| Joins are common | Embedding/references are common |
| Strong relational modeling | Flexible document modeling |
| Good for complex relationships and transactions | Good for flexible, large-scale document data |

### SQL example

```sql
SELECT * FROM employee
WHERE salary > 20000;
```

### MongoDB example

```javascript
db.employee.find({ salary: { $gt: 20000 } });
```

### When to use SQL

- Complex relationships.
- Strong consistency requirements.
- Reporting and joins.
- Structured data.
- Transactions across multiple related tables.

### When to use MongoDB

- Flexible or changing schema.
- JSON-like document data.
- Large volumes of semi-structured data.
- Applications requiring horizontal scalability.
- Content/catalog/profile data.

# Angular

## 22. What is Data Binding?

Data binding is the communication between the component class and the HTML template.

### Types of data binding

| Type | Syntax | Direction |
|---|---|---|
| Interpolation | `{{ value }}` | Component to view |
| Property binding | `[property]="value"` | Component to view |
| Event binding | `(event)="method()"` | View to component |
| Two-way binding | `[(ngModel)]="value"` | Both directions |

### Example

```html
<p>{{ name }}</p>

<button [disabled]="isDisabled">Save</button>

<button (click)="save()">Save</button>

<input [(ngModel)]="name">
```

---

## 23. Example of `*ngIf`

`*ngIf` conditionally displays or removes an element from the DOM.

```html
<p *ngIf="isLoggedIn">
    Welcome user
</p>
```

If `isLoggedIn` is true, the paragraph is displayed. Otherwise, it is not rendered.

### With else

```html
<p *ngIf="isLoggedIn; else loginTemplate">
    Welcome user
</p>

<ng-template #loginTemplate>
    Please log in
</ng-template>
```

### Angular 17+ note

The modern control-flow syntax is:

```html
@if (isLoggedIn) {
    <p>Welcome user</p>
} @else {
    <p>Please log in</p>
}
```

---

## 24. Example of `*ngFor`

`*ngFor` repeats an HTML element for every item in a collection.

```html
<ul>
    <li *ngFor="let employee of employees">
        {{ employee.name }}
    </li>
</ul>
```

### With index

```html
<li *ngFor="let employee of employees; let i = index">
    {{ i + 1 }} - {{ employee.name }}
</li>
```

### Angular 17+ note

The modern syntax is:

```html
@for (employee of employees; track employee.id) {
    <li>{{ employee.name }}</li>
}
```

# SOLID Principles

## 25. What are SOLID Principles?

SOLID is a set of five object-oriented design principles that help create maintainable, flexible, and testable software.

---

## S — Single Responsibility Principle

A class should have only one reason to change.

### Bad example

One class handles:

- Employee data.
- Database operations.
- Email notifications.
- Report generation.

### Better design

Separate responsibilities:

- `EmployeeService`
- `EmployeeRepository`
- `EmailService`
- `ReportService`

### Interview answer

“Each class should focus on one responsibility. This makes the code easier to maintain and test.”

---

## O — Open/Closed Principle

Software entities should be open for extension but closed for modification.

### Meaning

We should be able to add new behavior without changing stable existing code.

### Example

Instead of modifying a large `if-else` block for every payment type, create a common interface:

```java
interface Payment {
    void pay();
}
```

Then implement:

- `CardPayment`
- `UPIPayment`
- `CashPayment`

---

## L — Liskov Substitution Principle

A child class should be replaceable for its parent class without breaking the application.

### Example

If `Bird` has a `fly()` method, a `Penguin` should not inherit from it if penguins cannot fly.

### Interview answer

“Subclasses must honor the behavior expected from their parent class.”

---

## I — Interface Segregation Principle

A class should not be forced to implement methods it does not need.

### Bad example

One large interface contains printing, scanning, faxing, and copying methods. A basic printer may not support all of them.

### Better design

Split it into smaller interfaces:

- `Printer`
- `Scanner`
- `Fax`

---

## D — Dependency Inversion Principle

High-level modules should not depend directly on low-level modules. Both should depend on abstractions.

### Example

Instead of:

```java
class OrderService {
    private MySQLRepository repository = new MySQLRepository();
}
```

Use:

```java
class OrderService {
    private final OrderRepository repository;

    OrderService(OrderRepository repository) {
        this.repository = repository;
    }
}
```

Now `OrderService` depends on an interface, not a concrete implementation.

### Benefits

- Loose coupling.
- Easier unit testing.
- Easy replacement of implementations.
- Better maintainability.
