# Hotfoot Chennai -- Level 1 Interview Preparation

## Angular Questions: Signals, Services, Standalone Components, Closures, Component Communication & Duplicate Code

> **Interview style:** Keep answers short first. If the interviewer asks
> "why?" or "explain", use the detailed point below.

------------------------------------------------------------------------

# 1. Angular Signals

## What is a Signal in Angular?

### Speakable answer

> A Signal is Angular's reactive state primitive. It holds a value and
> notifies Angular when that value changes, so Angular can update the
> parts of the UI that depend on it.

Example:

``` typescript
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true,
  template: `
    <p>Count: {{ count() }}</p>
    <button (click)="increment()">Increment</button>
  `
})
export class CounterComponent {

  count = signal(0);

  increment() {
    this.count.update(value => value + 1);
  }
}
```

## Why do we use `count()`?

A Signal is a function-like reactive value.

``` typescript
count = signal(0);
```

Read:

``` typescript
count()
```

Update:

``` typescript
count.set(10);
```

or:

``` typescript
count.update(value => value + 1);
```

------------------------------------------------------------------------

# 2. set vs update in Signals

## `set()`

Use when you already know the new value.

``` typescript
count.set(10);
```

## `update()`

Use when the new value depends on the previous value.

``` typescript
count.update(value => value + 1);
```

### Interview answer

> `set()` directly replaces the signal value, while `update()`
> calculates the new value from the current value.

------------------------------------------------------------------------

# 3. computed() Signal

A `computed()` signal derives a value from other signals.

``` typescript
import { computed, signal } from '@angular/core';

count = signal(5);

doubleCount = computed(() => this.count() * 2);
```

Template:

``` html
<p>{{ count() }}</p>
<p>{{ doubleCount() }}</p>
```

If `count` changes, `doubleCount` is recalculated when needed.

### Interview answer

> I use `computed()` for derived state instead of manually maintaining
> another variable.

------------------------------------------------------------------------

# 4. effect()

`effect()` runs side-effect logic when the signals it reads change.

``` typescript
import { effect, signal } from '@angular/core';

name = signal('Priya');

constructor() {
  effect(() => {
    console.log('Name:', this.name());
  });
}
```

When:

``` typescript
this.name.set('Priyanka');
```

the effect reacts to the change.

### Important

Use `computed()` for derived values.

Use `effect()` for side effects such as:

-   logging
-   interacting with browser APIs
-   synchronizing external state

### Interview answer

> `computed()` is for deriving state, while `effect()` is for reacting
> to signal changes with side effects.

------------------------------------------------------------------------

# 5. Signals vs Observable

  -----------------------------------------------------------------------
  Signal                              Observable
  ----------------------------------- -----------------------------------
  Reactive state primitive            Reactive stream

  Very convenient for component state Excellent for async streams/events

  Read using `signal()`               Read using `subscribe()` / async
                                      pipe

  `set()` / `update()`                RxJS operators

  `computed()` for derived state      `map`, `filter`, `switchMap`, etc.

  Does not replace RxJS               Useful for HTTP, WebSockets and
                                      streams
  -----------------------------------------------------------------------

### Interview answer

> I use Signals mainly for reactive UI state and local or shared state.
> I use Observables when I am dealing with asynchronous streams such as
> HTTP, route parameters, WebSockets, or RxJS-based workflows. They can
> also be integrated together.

------------------------------------------------------------------------

# 6. Angular Service

## What is a Service?

### Speakable answer

> A service is a class used to keep reusable logic outside components. I
> commonly use services for API calls, shared state, authentication,
> business logic, and utility functionality.

Example:

``` typescript
import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root'
})
export class EmployeeService {

  getEmployees() {
    // HTTP call
  }
}
```

Component:

``` typescript
constructor(private employeeService: EmployeeService) {}
```

------------------------------------------------------------------------

# 7. Why use Services?

Without a service:

``` text
Component
   |
   +-- API call
   +-- business logic
   +-- validation
   +-- state
   +-- UI logic
```

This can become difficult to maintain.

With a service:

``` text
Component
    |
    v
Service
    |
    v
Backend API
```

### Benefits

-   Reusability
-   Separation of concerns
-   Easier testing
-   Centralized API logic
-   Shared state where appropriate
-   Cleaner components

### Interview answer

> I keep the component focused on presentation and user interaction,
> while the service handles reusable logic such as API communication or
> shared state.

------------------------------------------------------------------------

# 8. `providedIn: 'root'`

``` typescript
@Injectable({
  providedIn: 'root'
})
export class EmployeeService {
}
```

This tells Angular to make the service available through the root
injector.

It commonly results in a single service instance for the application's
root injector.

### Interview answer

> `providedIn: 'root'` registers the service with the root injector and
> makes it available throughout the application without needing to add
> it manually to a module providers array.

------------------------------------------------------------------------

# 9. What is Dependency Injection?

### Speakable answer

> Dependency Injection means a class receives the objects it depends on
> from Angular's injector instead of creating those objects itself.

Example:

``` typescript
constructor(
  private employeeService: EmployeeService
) {}
```

The component does not do:

``` typescript
new EmployeeService();
```

Angular provides the dependency.

### Why?

-   Loose coupling
-   Reusability
-   Testability
-   Easier maintenance

------------------------------------------------------------------------

# 10. Standalone Component

## What is a Standalone Component?

### Speakable answer

> A standalone component does not need to be declared in an NgModule. It
> can directly import the components, directives and pipes it needs.

Example:

``` typescript
import { Component } from '@angular/core';
import { CommonModule } from '@angular/common';

@Component({
  selector: 'app-employee',
  standalone: true,
  imports: [CommonModule],
  template: `
    <h2>Employees</h2>
  `
})
export class EmployeeComponent {
}
```

------------------------------------------------------------------------

# 11. Standalone Component vs NgModule

  Standalone                NgModule-based
  ------------------------- --------------------------------------
  `standalone: true`        Component declared in module
  Direct `imports`          Module manages declarations/imports
  Less module boilerplate   More module structure
  Good for modern Angular   Common in older Angular applications
  Easy lazy loading         Usually module-based lazy loading

### Interview answer

> Standalone components simplify Angular's dependency structure because
> the component directly declares the imports it needs. They also make
> lazy loading and application bootstrapping simpler.

------------------------------------------------------------------------

# 12. How do you bootstrap a Standalone Angular App?

Modern Angular commonly uses:

``` typescript
bootstrapApplication(AppComponent);
```

instead of:

``` typescript
platformBrowserDynamic()
  .bootstrapModule(AppModule);
```

Conceptually:

``` text
main.ts
   |
   v
bootstrapApplication()
   |
   v
Root Standalone Component
```

------------------------------------------------------------------------

# 13. Standalone Component Lazy Loading

You can lazy-load a standalone component:

``` typescript
{
  path: 'employees',
  loadComponent: () =>
    import('./employee/employee.component')
      .then(m => m.EmployeeComponent)
}
```

### Interview answer

> For a standalone component, I can use `loadComponent()` for lazy
> loading. It loads the component only when the route is requested.

------------------------------------------------------------------------

# 14. Component Communication

Angular components can communicate in several ways.

Main approaches:

1.  Parent → Child using `@Input`
2.  Child → Parent using `@Output`
3.  Sibling/unrelated components using a shared service
4.  Shared reactive state using Signals or RxJS
5.  Router parameters/state for route-based communication

------------------------------------------------------------------------

# 15. Parent → Child using @Input

Parent:

``` html
<app-child [employeeName]="name"></app-child>
```

Child:

``` typescript
@Input() employeeName = '';
```

Example:

``` typescript
@Component({
  selector: 'app-child',
  template: `
    <p>{{ employeeName }}</p>
  `
})
export class ChildComponent {

  @Input()
  employeeName = '';
}
```

### Interview answer

> For parent-to-child communication, I use `@Input`. The parent passes
> data through the child component's input property.

------------------------------------------------------------------------

# 16. Child → Parent using @Output

Child:

``` typescript
@Output()
employeeSelected = new EventEmitter<number>();

selectEmployee(id: number) {
  this.employeeSelected.emit(id);
}
```

Parent:

``` html
<app-child
  (employeeSelected)="onEmployeeSelected($event)">
</app-child>
```

Parent:

``` typescript
onEmployeeSelected(id: number) {
  console.log(id);
}
```

### Interview answer

> For child-to-parent communication, I use `@Output` with
> `EventEmitter`. The child emits an event and the parent listens to it.

------------------------------------------------------------------------

# 17. Sibling Component Communication

Suppose:

``` text
Component A
Component B
```

They don't have a direct parent-child relationship.

Use a shared service:

``` typescript
@Injectable({
  providedIn: 'root'
})
export class EmployeeStateService {

  selectedEmployee = signal<number | null>(null);
}
```

Component A:

``` typescript
this.state.selectedEmployee.set(101);
```

Component B:

``` typescript
employeeId = this.state.selectedEmployee;
```

Template:

``` html
<p>{{ employeeId() }}</p>
```

### Interview answer

> For sibling or unrelated components, I can use a shared service. With
> modern Angular, Signals are convenient for maintaining shared reactive
> state.

# 18. Closures in JavaScript

## What is a Closure?

### Speakable answer

> A closure happens when an inner function remembers and can access
> variables from its outer function even after the outer function has
> finished executing.

Example:

``` javascript
function counter() {

  let count = 0;

  return function () {
    count++;
    return count;
  };
}

const increment = counter();

console.log(increment()); // 1
console.log(increment()); // 2
console.log(increment()); // 3
```

The returned function still remembers `count`.

------------------------------------------------------------------------

# 19. Why does the Closure remember `count`?

Normally:

``` text
counter()
   |
   | creates count
   |
   v
returns inner function
```

Even after `counter()` finishes, the inner function still references
`count`.

Therefore JavaScript keeps the required lexical environment reachable.

### Important term

**Lexical scope**

The function remembers variables based on where the function was
defined.

------------------------------------------------------------------------

# 20. Real-world Closure Example

Private state:

``` javascript
function createBankAccount(initialBalance) {

  let balance = initialBalance;

  return {
    deposit(amount) {
      balance += amount;
    },

    getBalance() {
      return balance;
    }
  };
}

const account = createBankAccount(1000);

account.deposit(500);

console.log(account.getBalance()); // 1500
```

The `balance` variable cannot be accessed directly:

``` javascript
account.balance
```

It is protected through the closure.

### Interview answer

> Closures are useful for maintaining private state, callbacks, event
> handlers, and functions that need to remember their surrounding
> variables.

------------------------------------------------------------------------

# 21. Common Closure Interview Question

What is the output?

``` javascript
function outer() {

  let x = 10;

  function inner() {
    console.log(x);
  }

  return inner;
}

const fn = outer();

fn();
```

### Answer

``` text
10
```

Because `inner()` forms a closure over `x`.

# 22. Remove Duplicate Code -- What Does It Mean?

### Speakable answer

> I first identify repeated logic, then move the common logic into a
> reusable function, service, utility, directive, pipe, or shared
> component depending on the use case.

------------------------------------------------------------------------

# 23. Example -- Duplicate API Logic

Bad:

``` typescript
@Component({...})
export class EmployeeComponent {

  getEmployees() {
    this.http.get('/api/employees')
      .subscribe(data => {
        // logic
      });
  }
}
```

Another component:

``` typescript
@Component({...})
export class ManagerComponent {

  getEmployees() {
    this.http.get('/api/employees')
      .subscribe(data => {
        // same logic
      });
  }
}
```

This duplicates API logic.

Better:

``` typescript
@Injectable({
  providedIn: 'root'
})
export class EmployeeService {

  constructor(private http: HttpClient) {}

  getEmployees() {
    return this.http.get<Employee[]>('/api/employees');
  }
}
```

Both components use:

``` typescript
this.employeeService.getEmployees()
  .subscribe(data => {
    this.employees = data;
  });
```

------------------------------------------------------------------------

# 24. Duplicate UI Logic

If the same UI appears repeatedly:

``` html
<div class="employee-card">
  ...
</div>
```

Instead of repeating it:

``` html
<app-employee-card
  [employee]="employee">
</app-employee-card>
```

Create a reusable component.

### Rule of thumb

  Repeated thing        Possible solution
  --------------------- -----------------------------
  API logic             Service
  Utility function      Utility/helper
  UI                    Shared component
  Formatting            Pipe
  Reusable behavior     Directive
  Shared state          Service + Signal/Observable
  Repeated validation   Shared validator

------------------------------------------------------------------------

# 25. How Would You Refactor Duplicate Code?

### Strong Level 1 answer

> First I identify whether the duplication is UI logic, business logic,
> API logic, formatting, or state management. Then I move it to the
> appropriate reusable abstraction. For example, API calls go into a
> service, repeated UI goes into a reusable component, formatting goes
> into a pipe, and shared state can go into a service using Signals or
> Observables. I avoid over-abstraction if the code is only
> coincidentally similar.

------------------------------------------------------------------------

# 26. Scenario Question -- Employee Search

### Interviewer:

> You have EmployeeListComponent and ManagerListComponent. Both have the
> same API call and filtering logic. What will you do?

### Answer:

> I would move the API call into an EmployeeService. If the filtering
> logic is also reusable, I would move it into a utility function or
> service depending on whether it contains business logic. Each
> component would consume the reusable logic rather than duplicating it.

Example:

``` typescript
@Injectable({
  providedIn: 'root'
})
export class EmployeeService {

  constructor(private http: HttpClient) {}

  getEmployees() {
    return this.http.get<Employee[]>('/api/employees');
  }

  filterByDepartment(
    employees: Employee[],
    department: string
  ) {
    return employees.filter(
      employee => employee.department === department
    );
  }
}
```

# 27. Signals + Service -- Practical Example

A shared service can maintain state:

``` typescript
@Injectable({
  providedIn: 'root'
})
export class EmployeeStateService {

  private employeesSignal = signal<Employee[]>([]);

  employees = this.employeesSignal.asReadonly();

  setEmployees(employees: Employee[]) {
    this.employeesSignal.set(employees);
  }

  clearEmployees() {
    this.employeesSignal.set([]);
  }
}
```

Component:

``` typescript
employees = this.employeeState.employees;

constructor(
  private employeeState: EmployeeStateService
) {}
```

Template:

``` html
<div *ngFor="let employee of employees()">
  {{ employee.name }}
</div>
```

### Why `asReadonly()`?

It prevents consumers from directly changing the internal writable
signal.

The service controls updates through methods such as:

``` typescript
setEmployees()
clearEmployees()
```

# 31. One-Line Answers for Fast Interview Rounds

**What is Signal?**\
\> A reactive Angular state primitive that tracks changes and updates
dependent consumers.

**What is a service?**\
\> A reusable injectable class used for API calls, shared state, and
application logic.

**What is standalone component?**\
\> A component that can manage its own imports without being declared in
an NgModule.

**Parent to child?**\
\> `@Input`.

**Child to parent?**\
\> `@Output` with `EventEmitter`.

**Sibling communication?**\
\> Shared service using Signal or Observable.

**What is closure?**\
\> A function that retains access to variables from its lexical outer
scope.

**How do you remove duplicate API code?**\
\> Move common API logic into a reusable service.

**How do you remove duplicate UI?**\
\> Create a reusable component.

**Signals vs Observable?**\
\> Signals are convenient for reactive state; Observables are powerful
for asynchronous streams and RxJS workflows.
