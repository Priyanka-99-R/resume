## 1. Explain Change Detection in Angular

**Answer:**

Change detection is the process Angular uses to check whether component data has changed and update the DOM.

For example:

```ts
count = 0;

increment() {
  this.count++;
}
```

When `count` changes, Angular runs change detection and updates the UI.

### Main strategies

Angular provides two strategies:

- `Default`
- `OnPush`

**Default:** Angular checks the component and its child components during normal change-detection cycles.

**OnPush:** Angular checks the component mainly when specific triggers occur, such as an input reference change or an event inside the component.

### Interview line

> "Change detection is Angular's mechanism for keeping the component state and DOM in sync. I use OnPush where appropriate to reduce unnecessary checks and improve performance."

# 2. What is Zone.js?

**Answer:**

Zone.js is a library that helps Angular know when asynchronous operations have completed.

It can track operations such as:

- click events
- `setTimeout`
- HTTP requests
- promises
- DOM events

After an async operation completes, Zone.js notifies Angular, and Angular can start a change-detection cycle.

### Simple flow

```text
User/Event
   ↓
Async operation
   ↓
Zone.js detects completion
   ↓
Angular change detection
   ↓
DOM updated
```

### Interview line

> "Zone.js patches asynchronous browser APIs and helps Angular know when it should run change detection."

---

# 3. What is the role of Zone.js in Change Detection?

Zone.js does **not directly perform change detection**.

Its role is to notify Angular that an asynchronous task has completed.

Example:

```ts
setTimeout(() => {
  this.count++;
}, 1000);
```

The simplified flow is:

```text
setTimeout completes
       ↓
Zone.js detects it
       ↓
Angular is notified
       ↓
Change detection runs
       ↓
UI gets updated
```

### Important interview point

> "Zone.js is a mechanism that helps trigger Angular's change-detection process after asynchronous operations. Angular itself performs the change detection."

# 4. What is OnPush Change Detection?

`OnPush` is a change-detection strategy used to reduce unnecessary checks.

Example:

```ts
@Component({
  selector: 'app-user',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <p>{{ user.name }}</p>
  `
})
export class UserComponent {
  @Input() user!: User;
}
```

With OnPush, Angular does not continuously check the component in the same way as the Default strategy.

---

# 5. When is OnPush Change Detection Triggered?

This is a very important interview question.

Angular can check an OnPush component when:

### 1. An `@Input()` reference changes

```ts
this.user = {
  name: 'Priyanka'
};
```

This creates a new object reference.

But this may not trigger the expected OnPush update:

```ts
this.user.name = 'John';
```

because the object reference is still the same.

Better:

```ts
this.user = {
  ...this.user,
  name: 'John'
};
```

---

### 2. An event occurs inside the component

```html
<button (click)="increment()">+</button>
```

```ts
increment() {
  this.count++;
}
```

The event can cause Angular to check the component.

---

### 3. An observable used with `async` emits

```html
<div>{{ user$ | async }}</div>
```

The `async` pipe can mark the component for checking when a new value arrives.

---

### 4. A signal used by the template changes

```ts
count = signal(0);
```

```html
{{ count() }}
```

When the signal changes:

```ts
this.count.set(10);
```

Angular knows that the template depends on that signal and updates the relevant view.

---

### 5. Manual change detection

You can explicitly request checking using `ChangeDetectorRef`.

```ts
constructor(private cdr: ChangeDetectorRef) {}

this.cdr.markForCheck();
```

or:

```ts
this.cdr.detectChanges();
```

### `markForCheck()` vs `detectChanges()`

**markForCheck():**

> Marks the component/view to be checked during the next change-detection cycle.

**detectChanges():**

> Immediately runs change detection for that view and its children.

# 6. How would you use OnPush in a real project?

### Interview answer

> "In my Angular applications, I use OnPush for components where the data flow is predictable and mostly comes through Inputs, Observables, or Signals. I also avoid mutating objects directly because OnPush relies heavily on reference changes. For example, instead of modifying an existing user object, I create a new object using the spread operator. This reduces unnecessary change-detection work and improves performance, especially for large component trees."

Example:

```ts
this.user = {
  ...this.user,
  name: 'John'
};
```

# 7. ViewChild

`@ViewChild` is used to access a child component, directive, or DOM element from the component's **view/template**.

Example:

```html
<input #nameInput />
```

```ts
@ViewChild('nameInput')
nameInput!: ElementRef;
```

Then:

```ts
this.nameInput.nativeElement.focus();
```

### Accessing a child component

Parent:

```html
<app-child #child></app-child>
```

```ts
@ViewChild('child')
child!: ChildComponent;
```

Now the parent can access public properties/methods of the child.

### Interview line

> "ViewChild is used when the parent needs to access something that exists in its own template, such as a DOM element or child component."

---

# 8. ContentChild

`@ContentChild` is used to access content projected into a component using `ng-content`.

Example child component:

```html
<div class="container">
  <ng-content></ng-content>
</div>
```

Parent:

```html
<app-card>
  <p #description>Hello</p>
</app-card>
```

Child:

```ts
@ContentChild('description')
description!: ElementRef;
```

### Easy difference

```text
ViewChild
   ↓
Element/component inside my own template

ContentChild
   ↓
Content projected into my component using ng-content
```

### Interview line

> "ViewChild accesses elements from the component's own view, while ContentChild accesses projected content provided by the parent."

---

# 9. ViewChild vs ContentChild

| Feature | ViewChild | ContentChild |
|---|---|---|
| Accesses | Own template | Projected content |
| Related to | View | Content projection |
| Commonly used with | Template elements/components | `ng-content` |
| Example | `<input #input>` | `<ng-content>` |

# 11. Cold Observable vs Hot Observable

This is a common interview question.

## Cold Observable

A cold Observable starts its execution separately for each subscriber.

Example:

```ts
const observable$ = new Observable(observer => {
  console.log('API/operation executed');
  observer.next(Math.random());
});
```

If two subscribers subscribe:

```ts
observable$.subscribe();
observable$.subscribe();
```

the producer can execute separately for each subscriber.

### Simple definition

> "Cold Observable means each subscriber gets its own execution."

---

## Hot Observable

A hot Observable has a producer that can exist independently of individual subscribers.

Examples:

- `Subject`
- `BehaviorSubject`
- DOM events

Example:

```ts
const subject = new Subject<number>();

subject.subscribe(value => console.log('A:', value));

subject.next(10);

subject.subscribe(value => console.log('B:', value));

subject.next(20);
```

The second subscriber does not receive the earlier `10`.

### Simple definition

> "Hot Observable shares an existing producer, so subscribers can receive values from the shared stream."

---

# 12. Cold vs Hot – Easy Memory Trick

```text
Cold = each subscriber starts its own execution

Hot = producer already exists and values can be shared
```

# 13. Shared Service in Angular

A shared service is commonly used to share data or functionality between components.

Example:

```ts
@Injectable({
  providedIn: 'root'
})
export class UserService {

  private userSubject =
    new BehaviorSubject<User | null>(null);

  user$ = this.userSubject.asObservable();

  setUser(user: User) {
    this.userSubject.next(user);
  }
}
```

Component A:

```ts
this.userService.setUser(user);
```

Component B:

```ts
this.userService.user$.subscribe(user => {
  console.log(user);
});
```

### Interview line

> "I use a shared service when multiple components need to communicate or share application data without creating direct parent-child coupling."

# 14. Shared Service vs State Management

### Shared Service

Good for:

- small shared state
- communication between unrelated components
- simple application-level data
- reusable business logic

Example:

```ts
BehaviorSubject
Subject
Observable
```

### NgRx / State Management

Useful when the application has:

- complex global state
- many components consuming the same state
- predictable state transitions
- complex async workflows
- need for centralized debugging

Typical flow:

```text
Component
   ↓
Action
   ↓
Effect
   ↓
API
   ↓
Action
   ↓
Reducer
   ↓
Store
   ↓
Selector
   ↓
Component
```

### Interview answer

> "For simple shared state, I prefer a service with RxJS. When the application has complex global state, many consumers, and predictable state transitions are required, I use a state-management solution such as NgRx."

# 16. Print All Substrings of a String

Suppose:

```ts
const str = 'abc';
```

Expected substrings:

```text
a
ab
abc
b
bc
c
```

### Simple JavaScript solution

```ts
const str = 'abc';

for (let i = 0; i < str.length; i++) {
  let sub = '';

  for (let j = i; j < str.length; j++) {
    sub += str[j];
    console.log(sub);
  }
}
```

### How it works

For:

```text
abc
```

Start from index `0`:

```text
a
ab
abc
```

Start from index `1`:

```text
b
bc
```

Start from index `2`:

```text
c
```

---

# 17. Print All Substrings Using `substring()`

Another approach:

```ts
const str = 'abc';

for (let i = 0; i < str.length; i++) {
  for (let j = i + 1; j <= str.length; j++) {
    console.log(str.substring(i, j));
  }
}
```

This is also a good interview solution.

# 18. Get Difference Between Two Dates

JavaScript stores dates using `Date`.

Example:

```ts
const date1 = new Date('2026-10-01');
const date2 = new Date('2026-10-05');

const difference =
  date2.getTime() - date1.getTime();

const days =
  difference / (1000 * 60 * 60 * 24);

console.log(days);
```

Output:

```text
4
```

### Formula

```text
milliseconds
÷ 1000
÷ 60
÷ 60
÷ 24
= days
```

---

# 19. Safer Date Difference for Date-Only Values

For date-only interview examples, normalize the time:

```ts
const date1 = new Date('2026-10-01');
const date2 = new Date('2026-10-05');

const d1 = Date.UTC(
  date1.getFullYear(),
  date1.getMonth(),
  date1.getDate()
);

const d2 = Date.UTC(
  date2.getFullYear(),
  date2.getMonth(),
  date2.getDate()
);

const days = Math.abs(
  (d2 - d1) / (1000 * 60 * 60 * 24)
);

console.log(days);
```
