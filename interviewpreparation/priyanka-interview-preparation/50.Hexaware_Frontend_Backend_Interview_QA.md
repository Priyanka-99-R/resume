# 1. Angular / Frontend Interview

## 1. How does an Angular application run when we give `npm start`?

When I run `npm start`, Angular executes the `start` script from
`package.json`, usually `ng serve`.

The Angular CLI: 1. Compiles TypeScript and Angular templates. 2. Starts
the development server. 3. The browser loads `index.html`. 4. `main.ts`
bootstraps the Angular application. 5. The root component and router are
initialized. 6. The application is rendered in the browser.

**Speakable answer:** \> "`npm start` usually runs `ng serve`. Angular
compiles the application, starts the dev server, and the browser loads
`index.html`. From `main.ts`, Angular bootstraps the root application
and starts rendering the components and routes."

## 2. `@Input()` and `@Output()` with a scenario

-   `@Input()` → parent to child.
-   `@Output()` → child to parent.

### Parent

``` ts
@Component({
  selector: 'app-parent',
  template: `
    <app-child
      [userName]="userName"
      (messageEvent)="receiveMessage($event)">
    </app-child>
  `
})
export class ParentComponent {
  userName = 'Priyanka';

  receiveMessage(message: string) {
    console.log(message);
  }
}
```

### Child

``` ts
@Component({
  selector: 'app-child',
  template: `
    <p>{{ userName }}</p>
    <button (click)="sendMessage()">Send</button>
  `
})
export class ChildComponent {

  @Input() userName!: string;

  @Output() messageEvent = new EventEmitter<string>();

  sendMessage() {
    this.messageEvent.emit('Message from child');
  }
}
```

**Speakable answer:** \> "`@Input` is used when the parent needs to pass
data to the child. `@Output` is used when the child needs to send an
event back to the parent."

**Speakable answer:** \> "I mainly use guards for authentication and
route access. For example, before opening a dashboard, the guard checks
whether the user is logged in. If not, I redirect the user to login."

   ↓

# 8. SSR --- Core Issues and Handling

SSR means **Server-Side Rendering**.

The server generates the initial HTML and sends it to the browser.

### Common SSR issues

Browser-only APIs may not exist on the server:

``` ts
window
document
localStorage
sessionStorage
navigator
```

Another issue is **hydration mismatch**, when the HTML generated on the
server differs from what Angular expects on the client.

### Handling

Use browser checks:

``` ts
if (isPlatformBrowser(this.platformId)) {
  localStorage.getItem('token');
}
```

Also avoid random/time-dependent rendering that produces different
server and browser output.

**Speakable answer:** \> "The main SSR issue I have to consider is that
browser APIs like window, document and localStorage are not available
during server rendering. I handle browser-only code using platform
checks and make sure server and client rendering are consistent to avoid
hydration issues."

  --------------------------- ------------------------------------

Do **not** say:

> Template-driven = synchronous, Reactive = asynchronous.

Both forms can use **synchronous and asynchronous validators**.

availability.

**Speakable answer:** \> "The main difference is not synchronous versus
asynchronous. Both reactive and template-driven forms support sync and
async validation. I prefer reactive forms for complex forms because the
form structure and validation are easier to control from TypeScript."

# 16. What is Optional? Where should we use it?

`Optional<T>` represents a value that may or may not be present.

Good usage:

``` java
Optional<Employee> employee = employeeRepository.findById(id);
```

Then:

``` java
Employee employee = employeeRepository.findById(id)
        .orElseThrow(() -> new RuntimeException("Employee not found"));
```

### Avoid using Optional for

-   Entity fields
-   DTO fields in normal cases
-   Method parameters
-   Every local variable

**Speakable answer:** \> "I mainly use Optional as a return type when a
value may be absent, especially repository methods. I avoid using it
everywhere, such as entity fields and method parameters."

# 25. `==` vs `.equals()` and Memory

For objects:

-   `==` checks reference identity.
-   `equals()` checks logical equality when the class overrides it.

Example:

``` java
String a = new String("Java");
String b = new String("Java");

System.out.println(a == b);       // false
System.out.println(a.equals(b));  // true
```

### String pool

``` java
String x = "Java";
String y = "Java";

System.out.println(x == y); // true
```

Because string literals can refer to the same object in the String Pool.

**Speakable answer:** \> "`==` compares references for objects, while
`equals()` compares logical content when it is properly overridden.
String literals are stored in the String Pool, so two identical literals
can refer to the same object."

# 33. Longest Palindrome in a String

Use the expand-around-center approach.

``` java
public static String longestPalindrome(String s) {

    if (s == null || s.length() < 2) {
        return s;
    }

    int start = 0;
    int end = 0;

    for (int i = 0; i < s.length(); i++) {

        int len1 = expand(s, i, i);
        int len2 = expand(s, i, i + 1);

        int len = Math.max(len1, len2);

        if (len > end - start + 1) {
            start = i - (len - 1) / 2;
            end = i + len / 2;
        }
    }

    return s.substring(start, end + 1);
}

private static int expand(String s, int left, int right) {

    while (left >= 0
            && right < s.length()
            && s.charAt(left) == s.charAt(right)) {

        left--;
        right++;
    }

    return right - left - 1;
}
```

Time complexity: **O(n²)**.

# 46. Deadlock

Deadlock happens when threads wait indefinitely for locks held by each
other.

Example concept:

``` text
Thread 1 → Lock A → waits for Lock B
Thread 2 → Lock B → waits for Lock A
```

Prevention:

-   Consistent lock ordering
-   Avoid unnecessary nested locks
-   Keep lock scope small
-   Use `tryLock()` with timeout where appropriate
-   Take thread dumps when diagnosing

# 54. Singleton in Multithreading

A simple lazy singleton without synchronization can create multiple
instances when multiple threads call it simultaneously.

Thread-safe double-checked locking:

``` java
class Singleton {

    private static volatile Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {

        if (instance == null) {

            synchronized (Singleton.class) {

                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }

        return instance;
    }
}
```

A simpler lazy approach is the static holder pattern:

``` java
class Singleton {

    private Singleton() {
    }

    private static class Holder {
        private static final Singleton INSTANCE =
                new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
```

**Speakable answer:** \> "For a thread-safe lazy singleton, I can use
the static holder pattern or double-checked locking with volatile. The
holder pattern is simple because class initialization is thread-safe."

# 55. Missing Number

Question:

> Given numbers from `1` to `n` with one number missing, find the
> missing number.

Example:

``` text
Input:  [1,2,3,5]

```

### Formula approach

``` java
int n = numbers.length + 1;

```

### XOR approach

``` java
int xor = 0;

for (int i = 1; i <= n; i++) {
    xor ^= i;
}

for (int num : numbers) {
    xor ^= num;
}

System.out.println(xor);
```

# 66. Average Salary Greater Than 30000 --- SQL

If the question means:

> Find the average salary of employees whose salary is greater than
> 30000.

``` sql
SELECT AVG(salary) AS average_salary
FROM employee
WHERE salary > 30000;
```

If the question means:

> Find departments whose average salary is greater than 30000.

Then:

``` sql
SELECT department_id,
       AVG(salary) AS average_salary
FROM employee
GROUP BY department_id
HAVING AVG(salary) > 30000;
```

### Important difference

`WHERE` filters rows **before** grouping.

`HAVING` filters groups **after** `GROUP BY`.

# 6. Interview Answer Pattern

For experience-based questions, use:

**1. Definition → 2. Project usage → 3. Small example**

Example for interceptor:

> "An HTTP interceptor is used to intercept requests and responses
> globally. In my application, I use it mainly for adding the JWT token
> and common headers, and for handling common errors. So instead of
> adding the token manually in every service, the interceptor handles it
> centrally."

Example for `@Transactional`:

> "`@Transactional` defines a transaction boundary. In a business
> operation such as payment or money transfer, if multiple database
> operations need to succeed together, I put them inside a transaction
> so the database doesn't remain in a partially updated state."

Example for lazy loading:

> "Lazy loading loads a feature only when the user navigates to it. I
> use it for larger modules so the initial application bundle stays
> smaller and the initial load is faster."

# 7. Key Corrections to Remember

### Forms

Do **not** say:

> Template-driven = synchronous and Reactive = asynchronous.

Correct:

> Both can support synchronous and asynchronous validators. The main
> difference is how the form is structured and managed.

### Security

Do **not** say:

> Angular role checking alone provides security.

Correct:

> Angular handles UI/route experience, while backend authorization
> enforces security.

### PUT

Do **not** say:

> PUT is always only update.

Correct:

> PUT generally replaces a resource at a known URI and is commonly used
> for update operations.

### Optional

Do **not** say:

> Use Optional everywhere to avoid null.

Correct:

> Use it mainly where absence is a meaningful return value; avoid
> unnecessary Optional fields/parameters.

### Microservices

Do **not** say:

> Microservices are always better than monoliths.

Correct:

> They provide independent deployment/scaling but add distributed-system
> complexity. The choice depends on the application's requirements.
