# 1. Multithreading

### Question
**What is multithreading in Java?**

### Answer

Multithreading means executing multiple threads concurrently within the same process.

A thread is a lightweight unit of execution.

Example:

```java
class MyTask extends Thread {
    @Override
    public void run() {
        System.out.println("Task running");
    }
}

public class Main {
    public static void main(String[] args) {
        MyTask task = new MyTask();
        task.start();
    }
}
```

Important:

```text
start() → creates/schedules a new thread
run()   → contains the task logic
```

Do not normally call `run()` directly when you want a new thread.

### Interview line

> "Multithreading allows multiple tasks to make progress concurrently, which can improve responsiveness and throughput when used appropriately."

---

# 2. In Which Scenarios Do We Use Multithreading?

### Question
**When would you use multithreading in a real project?**

### Answer

I would use multithreading when tasks can run independently or when I want to avoid blocking the main execution flow.

Examples:

- Processing multiple independent records
- Sending notifications
- Background processing
- File processing
- Parallel API calls
- CPU-intensive tasks
- Scheduled/background jobs
- Processing large datasets
- Asynchronous event processing

Example:

```text
Request
  |
  +---- Task A
  |
  +---- Task B
  |
  +---- Task C
```

If A, B, and C are independent, they can potentially execute concurrently.

### Important

Do not use multithreading blindly. Creating too many threads can cause:

- context switching
- memory usage
- thread contention
- race conditions
- performance degradation

In modern Java applications, prefer managed executors/thread pools rather than creating unlimited threads manually.

# 3. Is Multithreading Synchronous or Asynchronous?

### Question
**Is multithreading synchronous or asynchronous?**

### Answer

Multithreading and synchronous/asynchronous execution are related concepts, but they are not exactly the same thing.

Multiple threads allow tasks to execute concurrently.

If the caller starts work and does not wait for its completion, the behavior can be asynchronous.

Example:

```java
ExecutorService executor = Executors.newFixedThreadPool(2);

executor.submit(() -> {
    System.out.println("Background task");
});

System.out.println("Main thread continues");
```

The main thread can continue while another thread executes the submitted task.

### Interview-safe answer

> "Multithreading enables concurrent execution. It can be used to implement asynchronous processing, but multithreading itself is not simply synonymous with asynchronous programming."

# 4. Is HashMap Thread-Safe?

### Question
**Is HashMap thread-safe?**

### Answer

No.

`HashMap` is not thread-safe for concurrent modification/access where synchronization is required.

Example:

```java
Map<String, Integer> map = new HashMap<>();
```

If multiple threads modify it concurrently, you can have race conditions and inconsistent results.

### Alternatives

For concurrent access:

```java
ConcurrentHashMap
```

or synchronization:

```java
Collections.synchronizedMap(...)
```

But these have different performance and behavior characteristics.

### Interview line

> "HashMap is not thread-safe. For concurrent access, I would consider ConcurrentHashMap or explicit synchronization depending on the use case."

---

# 5. Why is ConcurrentHashMap Thread-Safe?

### Question
**Why is ConcurrentHashMap thread-safe?**

### Answer

`ConcurrentHashMap` is designed for concurrent access.

It allows multiple threads to read and update the map safely without requiring one global lock around every operation.

Modern Java implementations use fine-grained synchronization and CAS-based techniques internally where appropriate.

Example:

```java
ConcurrentHashMap<String, Integer> map =
        new ConcurrentHashMap<>();

map.put("A", 100);
```

Multiple threads can work with the map concurrently while the implementation provides thread-safe operations.

### Important

`ConcurrentHashMap` does **not** mean that every sequence of multiple operations is automatically atomic.

For example:

```java
if (!map.containsKey(key)) {
    map.put(key, value);
}
```

The complete check-then-act sequence is not automatically atomic.

Use an atomic API such as:

```java
map.putIfAbsent(key, value);
```

### Interview line

> "ConcurrentHashMap provides thread-safe concurrent map operations using internal concurrency mechanisms, while allowing much more concurrency than synchronizing the entire map."

# 6. If HashMap Is Inside a Synchronized Block, Is It Thread-Safe?

### Question
**If HashMap is inside a synchronized block, is it thread-safe?**

### Answer

It can be thread-safe **if all access to that HashMap is properly protected by the same lock**.

Example:

```java
private final Map<String, Integer> map = new HashMap<>();
private final Object lock = new Object();

void put(String key, Integer value) {
    synchronized (lock) {
        map.put(key, value);
    }
}

Integer get(String key) {
    synchronized (lock) {
        return map.get(key);
    }
}
```

Here both read and write operations use the same lock.

But this is unsafe:

```java
synchronized (lock) {
    map.put(key, value);
}

map.get(key); // not protected
```

because another thread may access the map without the lock.

### Interview line

> "A HashMap can be safely shared if every access that requires synchronization is consistently protected by the same lock. Simply putting one operation in a synchronized block does not make the HashMap globally thread-safe."

# 7. Lambda Expression

### Question
**What is a Lambda Expression in Java?**

### Answer

A lambda expression is a concise way to represent a function-like piece of behavior, especially for functional interfaces.

Example:

```java
List<String> names = List.of("A", "B", "C");

names.forEach(name -> System.out.println(name));
```

Instead of:

```java
names.forEach(name -> {
    System.out.println(name);
});
```

A common functional interface example:

```java
Runnable task = () -> System.out.println("Running");
```

### Functional interface

An interface with exactly one abstract method.

Examples:

```text
Predicate
Function
Consumer
Supplier
Runnable
Comparator
```

### Interview line

> "Lambda expressions reduce boilerplate and allow behavior to be passed as a value, especially when working with functional interfaces and streams."

# 9. What Are Microservices?

### Question
**What are microservices?**

### Answer

Microservices is an architecture where an application is divided into small, independently deployable services.

Each service focuses on a specific business capability.

Example:

```text
                 API Gateway
                     |
       +-------------+-------------+
       |             |             |
   User Service   Order Service   Payment Service
       |             |             |
     DB/User       DB/Order      DB/Payment
```

### Advantages

- Independent deployment
- Independent scaling
- Better separation of business responsibilities
- Fault isolation
- Teams can work independently

### Challenges

- Network failures
- Distributed transactions
- Monitoring
- Logging/tracing
- Service communication
- Deployment complexity
- Data consistency

### Interview line

> "Microservices split a system by business capability into independently deployable services, but they introduce distributed-system complexity, so I would not use them simply for the sake of using microservices."

# 10. Microservice Design Patterns

Important patterns to know:

### API Gateway

Single entry point for clients.

```text
Client
  ↓
API Gateway
  ↓
Services
```

### Circuit Breaker

Prevents repeated calls to an unhealthy service.

```text
Service A → Service B
             ↓
          Failure
             ↓
      Circuit opens
```

### Retry

Retries transient failures.

Important: use carefully and preferably with backoff.

### Saga

Manages distributed business transactions using a sequence of local transactions and compensating actions.

### Service Discovery

Helps services locate other services.

### Database per Service

Each service owns its data rather than directly sharing another service's database.

### Bulkhead

Isolates resources so failure in one area does not consume everything.

### Event-Driven Architecture

Services communicate through events/messages.

# 11. What is AWS Lambda?

### Question
**What is AWS Lambda?**

### Answer

AWS Lambda is a serverless compute service.

You provide a function, and AWS runs it in response to events without requiring you to manage servers directly.

Example:

```text
S3 upload
   ↓
Lambda
   ↓
Process file
```

Possible triggers include:

- API Gateway
- S3
- EventBridge
- SQS
- SNS
- Scheduled events

### Advantages

- Server management handled by AWS
- Automatic scaling
- Pay based on execution/usage model
- Event-driven

### Limitations

- Execution limits
- Cold starts
- Stateless execution model
- Resource/runtime constraints

# 12. How Do You Integrate S3?

### Question
**How do you integrate Amazon S3 with a Java/Spring Boot application?**

### Answer

A common flow is:

```text
Angular
   ↓
Spring Boot API
   ↓
AWS SDK
   ↓
Amazon S3
```

Example concept:

```java
PutObjectRequest request =
        PutObjectRequest.builder()
                .bucket(bucketName)
                .key(fileName)
                .build();

s3Client.putObject(request, requestBody);
```

For downloading:

```java
GetObjectRequest request =
        GetObjectRequest.builder()
                .bucket(bucketName)
                .key(fileName)
                .build();

ResponseBytes<GetObjectResponse> response =
        s3Client.getObjectAsBytes(request);
```

### Better production approach

For large files, consider using pre-signed URLs so the browser can upload/download directly from S3.

```text
Angular
   ↓
Backend requests pre-signed URL
   ↓
S3
```

This reduces load on the backend.

### Security

Do not expose AWS access keys in Angular/frontend code.

Use:

- IAM roles
- least privilege
- environment/configuration management
- pre-signed URLs when appropriate

# 13. Angular Change Detection

### Question
**Explain change detection in Angular.**

### Answer

Change detection is how Angular checks component state and updates the DOM when values used by the template change.

Two important strategies:

```text
Default
OnPush
```

`OnPush` can reduce unnecessary checks.

### OnPush triggers

An OnPush component can be checked when:

- an input reference changes
- an event occurs in the component
- an Observable used through `async` emits

```ts

})
```

# 14. Angular Signals

### Question
**What are Signals in Angular?**

### Answer

Signals are a reactive primitive that stores a value and tracks which parts of the application depend on that value.

Example:

```ts
count = signal(0);

increment() {
    this.count.update(value => value + 1);
}
```

Template:

```html
<p>{{ count() }}</p>
```

When the signal changes, Angular knows that the template depends on it.

### Main APIs

```text
signal()
computed()
effect()
```

### Interview line

> "Signals provide fine-grained reactive state tracking and make it easier for Angular to know which views depend on a particular piece of state."

---

# 15. Computed vs Effect

## computed()

Use `computed()` for a derived value.

```ts
firstName = signal('Priyanka');
lastName = signal('R');

fullName = computed(() =>
    `${this.firstName()} ${this.lastName()}`
);
```

`fullName` is derived from other signals.

### Important

Computed values should be used for deriving state, not for side effects.

---

## effect()

Use `effect()` when you need a side effect in response to signal changes.

Example:

```ts
effect(() => {
    console.log(this.count());
});
```

The effect runs when the signal it reads changes.

Possible side effects:

- logging
- analytics
- integrating with external APIs/browser APIs
- synchronization with non-reactive systems

### Easy difference

```text
computed → calculate/derive a value

effect   → perform a side effect
```

# 16. Dependency Injection

### Question
**What is Dependency Injection in Angular?**

### Answer

Dependency Injection means a class receives the dependencies it needs instead of creating them manually.

Example:

```ts
@Injectable({
  providedIn: 'root'
})
export class UserService {
}
```

Component:

```ts
constructor(private userService: UserService) {}
```

Angular's injector creates/provides the service.

### Benefits

- Loose coupling
- Reusability
- Easier testing
- Centralized dependency management

### Modern Angular style

```ts
private userService = inject(UserService);
```

# 17. Memory Leak in Angular

### Question
**What causes memory leaks in Angular and how do you prevent them?**

Common causes:

- subscriptions not cleaned up
- event listeners not removed
- timers not cleared
- long-lived references
- improperly managed third-party libraries

Example risk:

```ts
ngOnInit() {
    this.service.data$.subscribe(data => {
        // ...
    });
}
```

### Solutions

Use the `async` pipe:

```html
{{ data$ | async }}
```

Or Angular's modern lifecycle-aware cleanup:

```ts
private destroyRef = inject(DestroyRef);

this.service.data$
  .pipe(takeUntilDestroyed(this.destroyRef))
  .subscribe();
```

For manually created resources, clean them up in the appropriate lifecycle hook.

### Interview line

> "I prefer async pipe or takeUntilDestroyed for subscriptions so cleanup happens automatically with the component lifecycle."

# 18. Lazy Loading

### Question
**What is lazy loading in Angular?**

### Answer

Lazy loading means loading a feature only when it is needed instead of loading everything during the initial application load.

Example:

```ts
{
  path: 'admin',
  loadComponent: () =>
    import('./admin/admin.component')
      .then(m => m.AdminComponent)
}
```

Or lazy-loaded routes:

```ts
{
  path: 'admin',
  loadChildren: () =>
    import('./admin/admin.routes')
      .then(m => m.ADMIN_ROUTES)
}
```

### Benefits

- smaller initial bundle
- faster startup
- better performance

# 19. How Do You Prevent XSS?

### Question
**How do you prevent Cross-Site Scripting in Angular?**

### Answer

Angular provides built-in sanitization for many template bindings.

Prefer:

```html
<div>{{ userInput }}</div>
```

instead of dynamically inserting raw HTML.

Be careful with:

```html
[innerHTML]
```

and especially avoid bypassing Angular security without validating/trusting the content.

Avoid unnecessary use of:

```ts
bypassSecurityTrustHtml()
```

### Additional protections

- validate/sanitize untrusted input
- use Content Security Policy where appropriate
- avoid constructing executable HTML/JS from user input
- keep dependencies updated
- use secure HTTP headers
- never trust data just because it came from an API

### Interview line

> "I rely on Angular's built-in sanitization, avoid unsafe DOM APIs and unnecessary bypassSecurityTrust calls, validate untrusted content, and use CSP/security headers as defense in depth."

# 20. What is Hydration?

### Question
**What is hydration in Angular?**

### Answer

Hydration is used with server-side rendering.

The server first generates HTML:

```text
Server
  ↓
HTML sent to browser
  ↓
Browser displays HTML
  ↓
Angular hydrates/reuses the server-rendered DOM
  ↓
Application becomes interactive
```

Without hydration, the browser may need to recreate much of the UI on the client.

### Benefits

- faster perceived loading
- better SEO support with SSR
- reduced unnecessary DOM recreation
- improved user experience

### Important

Hydration is not the same as SSR.

```text
SSR       → server generates HTML

Hydration → client Angular attaches/reactivates behavior on that HTML
```

# 21. HTTP Interceptor

### Question
**What is an HTTP interceptor in Angular?**

### Answer

An HTTP interceptor intercepts outgoing HTTP requests and incoming responses.

Common uses:

- attach JWT
- logging
- error handling
- loading indicators
- retry logic
- handling 401 responses

Example:

```ts
export const authInterceptor: HttpInterceptorFn =
  (req, next) => {

    const token = localStorage.getItem('token');

    const authReq = token
      ? req.clone({
          setHeaders: {
            Authorization: `Bearer ${token}`
          }
        })
      : req;

    return next(authReq);
  };
```

### Why `req.clone()`?

Angular HTTP requests are immutable.

Therefore, instead of changing the original request, we create a modified copy.

# 22. How to Handle 401 and Token Refresh?

### Question
**What happens when the access token expires?**

### Answer

Typical flow:

```text
API request
   ↓
401 Unauthorized
   ↓
Interceptor catches 401
   ↓
Call refresh-token API
   ↓
Get new access token
   ↓
Retry original request
```

### Important interview point

If multiple requests fail with 401 at the same time, do not call the refresh API multiple times.

Use a shared refresh state/queue so:

```text
Request A ─┐
Request B ─┼→ One refresh request
Request C ─┘
             ↓
        New access token
             ↓
     Retry A/B/C
```

### Interview line

> "I allow only one refresh operation at a time. Other failed requests wait for the refresh result and are retried with the new access token."

# 29. Important Security Interview Scenario

### Question
**What if a user changes the JWT payload from USER to ADMIN?**

Suppose:

```text
HEADER.PAYLOAD.SIGNATURE
```

Original:

```json
{
  "role": "USER"
}
```

Attacker changes it to:

```json
{
  "role": "ADMIN"
}
```

The signature no longer matches the modified payload.

The server validates the JWT signature.

Therefore, the modified token should be rejected.

### Important

> "The frontend must never be the final authority for authorization. The backend validates the token and checks the user's permissions."
