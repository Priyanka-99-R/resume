# Friday Evening Interview Preparation – Java

## 1. Non-Heap Memory in Java

### What is non-heap memory?

Java memory is broadly divided into **Heap** and **Non-Heap** memory.

- **Heap:** Stores objects and arrays created using `new`.
- **Non-Heap:** Stores JVM-level data such as:
  - Metaspace – class metadata
  - Code Cache – JIT-compiled native code
  - Thread Stacks – each thread has its own stack
  - Native memory used by the JVM

### What is Metaspace?

Metaspace stores class metadata such as class definitions, methods, and field information.

Since Java 8, Metaspace replaced the old PermGen area.

### Interview answer

> Heap is mainly used for objects, while non-heap memory is used by the JVM for class metadata, compiled code, and other runtime structures. In Java 8+, class metadata is stored in Metaspace.

# 2. Multithreading

### What is multithreading?

Multithreading means executing multiple threads concurrently within a process.

It helps improve responsiveness and allows independent tasks to execute concurrently.

### How can we create a thread?

Two common approaches:

1. Extend `Thread`
2. Implement `Runnable`

For real applications, using `ExecutorService` is generally preferred because it manages a thread pool.

### Example

```java
ExecutorService executor = Executors.newFixedThreadPool(2);

executor.submit(() -> {
    System.out.println("Task running");
});

executor.shutdown();
```

### Interview answer

> Multithreading allows multiple tasks to execute concurrently. In production applications, I prefer ExecutorService or a thread pool instead of creating threads manually because it provides better thread management and resource control.

# 3. Runnable vs Callable

| Runnable | Callable |
|---|---|
| Introduced before Callable | Java 5 |
| `run()` method | `call()` method |
| Does not return a result | Can return a result |
| Cannot throw checked exception directly | Can throw checked exception |
| Used for tasks without a return value | Used when a task needs to return a result |

### Runnable

```java
Runnable task = () -> {
    System.out.println("Running task");
};
```

### Callable

```java
Callable<Integer> task = () -> {
    return 100;
};

ExecutorService executor = Executors.newSingleThreadExecutor();

Future<Integer> future = executor.submit(task);

Integer result = future.get();

executor.shutdown();
```

### Interview answer

> Runnable is used when the task does not need to return a value. Callable can return a value through Future and can throw checked exceptions.

# 4. Records in Java

A **record** is a concise way to create an immutable data carrier.

Records were introduced as a preview feature in Java 14 and became permanent in Java 16.

### Example

```java
public record Employee(int id, String name, double salary) {
}
```

Java automatically provides:

- Constructor
- Accessor methods such as `id()` and `name()`
- `equals()`
- `hashCode()`
- `toString()`

### Usage

```java
Employee employee = new Employee(1, "Priyanka", 50000);

System.out.println(employee.name());
System.out.println(employee.salary());
```

### Important point

Record components are final references, so you cannot reassign them.

```java
employee.name = "Test"; // Compile error
```

### Interview answer

> I use records mainly for immutable DTO-style data transfer objects where I don't need setters or mutable state.

# 5. OutOfMemoryError

### What is OutOfMemoryError?

`OutOfMemoryError` occurs when the JVM cannot allocate enough memory for an object or required JVM operation.

It is an `Error`, not an `Exception`.

### Common causes

- Creating too many objects
- Memory leak
- Large collections
- Objects retained unnecessarily
- Excessive caching
- Large file/data processing
- Insufficient heap configuration

### Example

```java
List<byte[]> list = new ArrayList<>();

while (true) {
    list.add(new byte[1024 * 1024]);
}
```

This can eventually cause heap exhaustion.

---

# 6. How do you identify OutOfMemoryError?

### Interview answer

> First I check application logs and JVM monitoring. I look at heap usage, GC activity, and the type of OutOfMemoryError. If necessary, I take a heap dump and analyze it using tools such as Eclipse MAT or VisualVM to identify which objects are consuming memory and why they are still referenced.

### Useful JVM options

```text
-XX:+HeapDumpOnOutOfMemoryError
-XX:HeapDumpPath=/path/to/dump
```

This automatically creates a heap dump when an OutOfMemoryError occurs.

---

# 7. Heap Memory – Why does it increase?

Heap memory increases when the application creates objects.

Normally, unused objects become eligible for garbage collection.

If heap usage keeps increasing, possible reasons are:

1. Memory leak
2. Long-lived references
3. Static collections
4. Unbounded cache
5. Large objects
6. Objects stored in sessions
7. Incorrect application logic

### Important distinction

> High heap usage is not automatically a memory leak. The important thing is whether memory is reclaimed after garbage collection.

---

# 8. How do you handle increasing heap memory?

### Step-by-step production approach

1. Check JVM heap metrics.
2. Check GC logs and GC frequency.
3. Identify whether memory is reclaimed after GC.
4. Capture a heap dump.
5. Analyze retained objects.
6. Find the application code holding unnecessary references.
7. Fix the root cause.
8. Tune cache/collection size if necessary.
9. Only after investigation, consider increasing `-Xmx`.

### Interview answer

> I would not immediately increase the heap size. First I would identify whether the increase is expected or caused by a memory leak. I would analyze GC behavior and a heap dump, identify the objects with high retained memory, fix the reference or caching issue, and then tune the JVM memory if required.

# 9. Custom Exception

A custom exception is an application-specific exception created by extending `Exception` or `RuntimeException`.

### Checked custom exception

```java
public class EmployeeNotFoundException extends Exception {

    public EmployeeNotFoundException(String message) {
        super(message);
    }
}
```

### Unchecked custom exception

```java
public class EmployeeNotFoundException extends RuntimeException {

    public EmployeeNotFoundException(String message) {
        super(message);
    }
}
```

### Spring Boot example

```java
@ResponseStatus(HttpStatus.NOT_FOUND)
public class EmployeeNotFoundException extends RuntimeException {

    public EmployeeNotFoundException(String message) {
        super(message);
    }
}
```

Usage:

```java
Employee employee = repository.findById(id)
        .orElseThrow(() ->
                new EmployeeNotFoundException("Employee not found: " + id));
```

### Interview answer

> I create custom exceptions when I want to represent a business-specific failure clearly. In Spring Boot, I generally use RuntimeException and handle it centrally using `@RestControllerAdvice`.

# 10. Comparison and Swap

### What is comparison and swap?

Compare-and-swap, or **CAS**, is an atomic operation used in concurrent programming.

It checks whether a value is still equal to an expected value. If yes, it replaces it with a new value.

### Example using AtomicInteger

```java
AtomicInteger count = new AtomicInteger(10);

boolean updated = count.compareAndSet(10, 20);

System.out.println(updated); // true
System.out.println(count.get()); // 20
```

If the current value is not `10`, the update will not happen.

### Interview answer

> Compare-and-swap is a lock-free atomic operation. It compares the current value with an expected value and updates it only when they match. Classes such as AtomicInteger use CAS internally.

# 11. map() vs flatMap()

Both are Stream API operations.

## map()

`map()` transforms each element into another element.

Example:

```java
List<String> names = List.of("java", "spring");

List<Integer> lengths = names.stream()
        .map(String::length)
        .toList();

System.out.println(lengths);
```

Output:

```text
[4, 6]
```

## flatMap()

`flatMap()` is used when each element produces multiple elements and we want one flattened stream.

Example:

```java
List<List<Integer>> numbers = List.of(
        List.of(1, 2),
        List.of(3, 4)
);

List<Integer> result = numbers.stream()
        .flatMap(List::stream)
        .toList();

System.out.println(result);
```

Output:

```text
[1, 2, 3, 4]
```

### Interview answer

> `map()` performs one-to-one transformation, while `flatMap()` is used when each element can produce multiple elements and we need to flatten them into a single stream.

# 12. Concurrency vs Parallelism

### Concurrency

Multiple tasks are in progress during the same time period. They may take turns executing.

### Parallelism

Multiple tasks actually execute at the same time, usually on multiple CPU cores.

### Simple example

> Concurrency is about dealing with multiple tasks at once. Parallelism is about executing multiple tasks at the same time.

### Interview example

A single-core system can provide concurrency through time-slicing.

A multi-core system can execute independent tasks in parallel.

# 13. Set vs TreeSet

| Set | TreeSet |
|---|---|
| Interface | Class |
| Does not allow duplicate elements | Does not allow duplicates |
| Ordering depends on implementation | Maintains sorted order |
| `HashSet`, `LinkedHashSet`, `TreeSet` implement Set | Implements `NavigableSet`/`SortedSet` |
| General abstraction | Sorted set implementation |

### HashSet

```java
Set<Integer> set = new HashSet<>();

set.add(30);
set.add(10);
set.add(20);
set.add(10);

System.out.println(set);
```

Duplicates are removed, but order is not guaranteed.

### TreeSet

```java
Set<Integer> set = new TreeSet<>();

set.add(30);
set.add(10);
set.add(20);
set.add(10);

System.out.println(set);
```

Output:

```text
[10, 20, 30]
```

### Interview answer

> Set is an interface representing a collection that doesn't allow duplicates. TreeSet is an implementation that additionally maintains elements in sorted order.

# 14. Coding – Find One Missing Number

### Question

Given an array containing numbers from `1` to `n` with one number missing, find the missing number.

Example:

```text
Input:  [1, 2, 4, 5]
Output: 3
```

## Approach 1 – Sum

Expected sum:

```text
n * (n + 1) / 2
```

Then:

```text
missing = expectedSum - actualSum
```

### Code

```java
public static int findMissing(int[] arr, int n) {

    int expectedSum = n * (n + 1) / 2;

    int actualSum = 0;

    for (int num : arr) {
        actualSum += num;
    }

    return expectedSum - actualSum;
}
```

### Complexity

- Time: `O(n)`
- Space: `O(1)`

### Interview explanation

> Since the range is 1 to n, I calculate the expected sum and subtract the actual array sum. The difference is the missing number.

# 15. Coding – Find Two Missing Numbers

### Question

Given numbers from `1` to `n`, where exactly two numbers are missing, find the two missing numbers.

Example:

```text
Input:  [1, 2, 5, 6]
n = 6

Missing: 3, 4
```

## Approach

Let the missing numbers be `x` and `y`.

First calculate:

```text
x + y = expectedSum - actualSum
```

Then use the sum of squares:

```text
x² + y² = expectedSquareSum - actualSquareSum
```

But for interviews, a simpler and safer approach is to use a boolean array when extra space is acceptable.

## Simple approach

```java
public static void findTwoMissing(int[] arr, int n) {

    boolean[] present = new boolean[n + 1];

    for (int num : arr) {
        present[num] = true;
    }

    for (int i = 1; i <= n; i++) {
        if (!present[i]) {
            System.out.println(i);
        }
    }
}
```

### Example

```java
int[] arr = {1, 2, 5, 6};

findTwoMissing(arr, 6);
```

Output:

```text
3
4
```

### Complexity

- Time: `O(n)`
- Space: `O(n)`

# 16. Two Missing Numbers – O(1) Extra Space Approach

If the interviewer asks for **constant extra space**, use XOR.

Let the missing numbers be `x` and `y`.

XOR all numbers from `1` to `n` and all elements in the array.

The result is:

```text
x ^ y
```

Find one set bit from that result to divide numbers into two groups, then XOR each group separately.

### Code

```java
public static int[] findTwoMissing(int[] arr, int n) {

    int xor = 0;

    // XOR all numbers from 1 to n
    for (int i = 1; i <= n; i++) {
        xor ^= i;
    }

    // XOR all array elements
    for (int num : arr) {
        xor ^= num;
    }

    // Rightmost set bit
    int bit = xor & -xor;

    int x = 0;
    int y = 0;

    for (int i = 1; i <= n; i++) {
        if ((i & bit) != 0) {
            x ^= i;
        } else {
            y ^= i;
        }
    }

    for (int num : arr) {
        if ((num & bit) != 0) {
            x ^= num;
        } else {
            y ^= num;
        }
    }

    return new int[]{x, y};
}
```

### Interview explanation

> XOR cancels identical numbers because `a ^ a = 0`. After XORing the complete range and the array, only the two missing numbers remain. I use a distinguishing set bit to separate the two missing numbers into different groups and find each one.

# 17. Bean Lifecycle in Spring

The Spring Bean lifecycle describes what happens from bean creation until bean destruction.

### Main flow

```text
Spring Container Starts
        ↓
Bean Definition
        ↓
Bean Instantiation
        ↓
Dependency Injection
        ↓
Aware callbacks
        ↓
BeanPostProcessor - Before Initialization
        ↓
@PostConstruct
        ↓
InitializingBean.afterPropertiesSet()
        ↓
Custom init method
        ↓
BeanPostProcessor - After Initialization
        ↓
Bean is Ready
        ↓
Application Running
        ↓
Container Shutdown
        ↓
@PreDestroy
        ↓
DisposableBean.destroy()
        ↓
Custom destroy method
```

## Example

```java
@Component
public class EmployeeService {

    @PostConstruct
    public void init() {
        System.out.println("Bean initialized");
    }

    @PreDestroy
    public void destroy() {
        System.out.println("Bean destroyed");
    }
}
```

### `@PostConstruct`

Called after dependency injection is completed.

### `@PreDestroy`

Called before the bean is destroyed when the Spring context shuts down.

### InitializingBean

```java
public class EmployeeService implements InitializingBean {

    @Override
    public void afterPropertiesSet() {
        System.out.println("Initialization completed");
    }
}
```

### DisposableBean

```java
public class EmployeeService implements DisposableBean {

    @Override
    public void destroy() {
        System.out.println("Bean destroyed");
    }
}
```

### Interview answer

> First Spring creates the bean and injects its dependencies. Then initialization callbacks such as `@PostConstruct` and `afterPropertiesSet()` are executed, along with BeanPostProcessor callbacks. After initialization the bean is ready for use. During application shutdown, destruction callbacks such as `@PreDestroy` are executed.
