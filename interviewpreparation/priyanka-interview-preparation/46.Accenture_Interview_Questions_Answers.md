# 1. Angular vs React — What is the difference?

### Short interview answer

> **Angular is a complete framework**, while **React is a JavaScript library mainly used for building the UI**.
>
> Angular provides many things out of the box, such as routing, dependency injection, forms, HTTP client, and a structured application architecture.
>
> With React, we usually choose additional libraries for routing, state management, and other requirements.
>
> Angular uses **TypeScript** heavily and follows a more structured approach. React uses **JSX** and gives more flexibility.
>
> I would choose Angular when the project needs a structured enterprise application, while React is a good choice when we want more flexibility and a lightweight UI library.

### Comparison

| Feature | Angular | React |
|---|---|---|
| Type | Full framework | UI library |
| Language | TypeScript | JavaScript / TypeScript |
| Architecture | More opinionated / structured | More flexible |
| Routing | Angular Router | Usually React Router |
| Forms | Built-in Forms / Reactive Forms | Usually external libraries |
| HTTP | HttpClient | Usually fetch / Axios |
| Dependency Injection | Built-in | Not built-in in the same way |
| UI | Templates + components | JSX + components |
| Best fit | Large structured applications | Flexible UI applications |

### Project example

> In my project, I use Angular with TypeScript. Angular handles components, routing, reactive forms, HTTP communication, and dependency injection. The Angular frontend communicates with the Spring Boot REST APIs.

# 2. Angular application is taking too much time to load. How do you debug it?

### Interview-ready answer

> First, I would identify **where the delay is happening** instead of immediately changing the code.
>
> I would open the browser **DevTools** and check the **Network tab** to see whether the problem is caused by large JavaScript bundles, slow API calls, large images, or other resources.
>
> Then I would use the **Performance tab** and Angular profiling tools to identify expensive rendering or change-detection work.
>
> I would also check the application's bundle size and use **lazy loading** for feature modules or routes that are not required during initial loading.
>
> On the code side, I would check unnecessary API calls, subscriptions, heavy operations in templates, large lists, and unnecessary change detection.
>
> Finally, I would optimize the actual bottleneck and measure the improvement again.

### Debugging checklist

1. Open **Chrome DevTools → Network**
2. Check:
   - JavaScript bundle size
   - API response time
   - Images/assets
   - Number of requests
3. Check **Performance**
4. Check Angular change detection / rendering
5. Check unnecessary API calls
6. Check large components and lists
7. Use lazy loading
8. Use `OnPush` where appropriate
9. Optimize images and static assets
10. Build using production configuration and compare bundle sizes

### Strong practical answer

> For example, if the initial JavaScript bundle is very large because several feature areas are loaded immediately, I would introduce route-level lazy loading so those features are downloaded only when the user navigates to them.

# 3. Is lazy loading necessary in Angular?

### Short answer

> **Lazy loading is not always necessary, but it is very useful for large applications.** It depends on the application size and user requirements.

### Explanation

Without lazy loading:

```text
Application starts
      ↓
Loads many features
      ↓
Large initial bundle
      ↓
Longer initial load
```

With lazy loading:

```text
Application starts
      ↓
Loads only required feature
      ↓
User navigates to another feature
      ↓
That feature is loaded
```

### Example

```typescript
const routes: Routes = [
  {
    path: 'admin',
    loadChildren: () =>
      import('./admin/admin.module')
        .then(m => m.AdminModule)
  }
];
```

### Interview answer

> I would use lazy loading when the application has multiple large feature areas, such as Admin, Reports, and User Management. It reduces the initial bundle and improves the initial loading experience. For a very small application, adding lazy loading everywhere may add unnecessary complexity.

---

# 4. Is lazy loading good or bad?

### Answer

> **Lazy loading is generally good, but it depends on the requirement.** It improves initial loading because we don't download every feature at startup. However, when the user opens a lazy-loaded feature for the first time, there can be a small delay while that chunk is downloaded.
>
> So I use lazy loading for larger or less frequently used features, while keeping critical features in the initial bundle.

### Advantages

- Smaller initial bundle
- Faster initial application load
- Better scalability
- Loads features only when required

### Disadvantages

- First navigation to a lazy feature can have a loading delay
- More chunks to manage
- Too much lazy loading can make the application unnecessarily complex

### Best interview phrase

> **"Lazy loading is not automatically good or bad; it depends on the application size, feature usage, and user experience requirements."**

# 5. What are Java Records?

### Short interview answer

> A **record** is a special type of class introduced in **Java 16** for creating simple immutable data carriers with less boilerplate.
>
> The compiler automatically provides the constructor, accessor methods, `equals()`, `hashCode()`, and `toString()`.

### Example

```java
public record Employee(
    String name,
    int age
) {}
```

Instead of writing a normal DTO with getters, constructor, `equals`, `hashCode`, and `toString`, a record provides these automatically.

### Usage

```java
Employee employee = new Employee("Priyanka", 25);

System.out.println(employee.name());
System.out.println(employee.age());
```

### Important point

Records are intended mainly for **data carriers**.

They are shallowly immutable: the record fields cannot be reassigned, but an object referenced by a field can still itself be mutable.

### Spring Boot example

> I can use a record as a DTO for request or response data when I don't need the DTO's state to change.

```java
public record StudentResponse(
    Long id,
    String name,
    String email
) {}
```

### Interview follow-up

**Q: Can a record extend another class?**

> No. A record implicitly extends `java.lang.Record`, so it cannot extend another class. It can implement interfaces.

# 6. What is Optional in Java?

### Short interview answer

> `Optional` is a container object that represents either a value being present or no value being present. It was introduced in Java 8 and is mainly useful for making the absence of a return value explicit and reducing accidental null handling.

### Example

```java
Optional<String> name = Optional.of("Priyanka");

System.out.println(name.get());
```

### Creating Optional

```java
Optional<String> a = Optional.of("Hello");

Optional<String> b = Optional.ofNullable(null);

Optional<String> c = Optional.empty();
```

### Important difference

```java
Optional.of(null);        // NullPointerException
Optional.ofNullable(null); // Optional.empty()
```

### Common methods

```java
isPresent()
isEmpty()
orElse()
orElseGet()
orElseThrow()
map()
filter()
```

### Practical example

```java
Optional<Employee> employee =
        employeeRepository.findById(10L);

String name = employee
        .map(Employee::getName)
        .orElse("Unknown");
```

### Best practice

> I mainly use `Optional` as a return type when a value may be absent. I generally avoid using it as an entity field, method parameter, or collection element unless there is a specific reason.

# 7. WHERE vs HAVING — What is the difference?

### Short interview answer

> **WHERE filters rows before grouping**, while **HAVING filters groups after `GROUP BY`**.
>
> `WHERE` is normally used for normal row-level conditions, whereas `HAVING` is commonly used with aggregate functions such as `COUNT`, `SUM`, and `AVG`.

### Example

Suppose we have:

```text
Employee
----------------
department | salary
IT         | 50000
IT         | 60000
HR         | 40000
HR         | 45000
```

### WHERE

```sql
SELECT *
FROM Employee
WHERE salary > 50000;
```

It filters individual rows.

### HAVING

```sql
SELECT department, AVG(salary)
FROM Employee
GROUP BY department
HAVING AVG(salary) > 50000;
```

It filters the groups.

### Easy memory trick

```text
WHERE  → rows
GROUP BY → groups
HAVING → groups after grouping
```

### Can WHERE and HAVING be used together?

Yes.

```sql
SELECT department, AVG(salary)
FROM Employee
WHERE salary > 40000
GROUP BY department
HAVING AVG(salary) > 50000;
```

Here:

1. `WHERE` removes rows first.
2. `GROUP BY` creates groups.
3. `HAVING` filters the resulting groups.

# 8. What are indexes in SQL?

### Short interview answer

> An **index** is a database data structure that helps the database find rows faster without scanning the entire table.
>
> It is useful especially for columns frequently used in `WHERE`, `JOIN`, `ORDER BY`, and sometimes `GROUP BY` operations.
>
> The trade-off is that indexes consume storage and can make `INSERT`, `UPDATE`, and `DELETE` operations more expensive because the index also needs to be maintained.

### Example

```sql
CREATE INDEX idx_employee_email
ON Employee(email);
```

Now a query such as:

```sql
SELECT *
FROM Employee
WHERE email = 'test@example.com';
```

may be able to use the index instead of scanning every row.

### Important point

An index does **not** guarantee that a query will use it. The database optimizer decides whether an index is beneficial.

### Advantages

- Faster searches
- Faster joins in appropriate cases
- Can help sorting/filtering

### Disadvantages

- Additional storage
- Slower writes
- Too many indexes can hurt performance

### Interview follow-up

**Q: Should we create an index on every column?**

> No. Too many indexes increase storage and write overhead. I would create indexes based on actual query patterns and verify their usefulness using the database execution plan.

# 9. When creating a table, is a default index automatically created?

### Important answer

> **Not for every column.** Creating a table does not automatically create an index on every column.
>
> However, when we define certain constraints, the database may automatically create an index or index-like structure depending on the database system. A **primary key** is commonly backed by a unique index, and a **UNIQUE constraint** is also commonly enforced using a unique index.
>
> The exact behavior depends on the database.

### Example

```sql
CREATE TABLE Employee (
    id INT PRIMARY KEY,
    email VARCHAR(255) UNIQUE,
    name VARCHAR(100)
);
```

Typically:

- `id` → primary-key constraint, commonly backed by an index
- `email` → unique constraint, commonly backed by a unique index
- `name` → **no automatic index just because the column exists**

### Strong interview answer

> "A normal column does not automatically get an index. Primary-key and unique constraints are typically backed by indexes, but the exact implementation depends on the database engine."

# 10. What is ExecutorService in Java?

### Short interview answer

> `ExecutorService` is a Java framework for managing and executing tasks using a pool of threads. Instead of manually creating a new thread for every task, we submit tasks to an executor, which manages the worker threads.

### Simple example

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Main {
    public static void main(String[] args) {

        ExecutorService executor =
                Executors.newFixedThreadPool(3);

        executor.submit(() ->
                System.out.println("Task 1"));

        executor.submit(() ->
                System.out.println("Task 2"));

        executor.shutdown();
    }
}
```

### How it works

```text
Application
    |
    | submit task
    ↓
ExecutorService
    |
    ↓
Thread Pool
 ┌──────┬──────┬──────┐
 T1     T2     T3
 └──────┴──────┴──────┘
    |
    ↓
Execute tasks
```

### Common implementations

```java
Executors.newFixedThreadPool(5);

Executors.newCachedThreadPool();

Executors.newSingleThreadExecutor();

Executors.newScheduledThreadPool(2);
```

### `submit()` vs `execute()`

```java
executor.execute(task);
```

`execute()` is used for a `Runnable` and does not return a result.

```java
Future<Integer> future =
        executor.submit(() -> 10 + 20);
```

`submit()` returns a `Future`, which can be used to get the result or check/cancel the task.

### Getting the result

```java
Future<Integer> future =
        executor.submit(() -> 10 + 20);

Integer result = future.get();

System.out.println(result);
```

Output:

```text
30
```

### Important interview point

> Always shut down an `ExecutorService` when it is no longer needed, otherwise its worker threads may keep the application alive.

```java
executor.shutdown();
```

### Real-world example

> In a backend application, if I need to perform several independent background tasks, such as processing files or calling independent services, I can use an `ExecutorService` instead of manually creating threads. The thread pool controls how many tasks execute concurrently.

# 🔴 Output-Based Questions

These questions are especially important because the interviewer may expect you to identify whether the code **compiles**, throws an exception, or produces normal output.

---

## Output Question 1

```java
import java.util.Optional;

public class Test1 {
    public static void main(String[] args) {

        Optional<Integer> inputNumber = Optional.of(null);

        System.out.println(inputNumber);
    }
}
```

### Answer

```text
NullPointerException
```

### Why?

`Optional.of()` does **not allow null**.

```java
Optional.of(null);
```

throws `NullPointerException` immediately.

The `System.out.println()` line is never reached.

### Correct alternative

```java
Optional<Integer> inputNumber =
        Optional.ofNullable(null);

System.out.println(inputNumber);
```

Output:

```text
Optional.empty
```

### Memory trick

```text
of(null)        → NPE
ofNullable(null) → Optional.empty
```

# Output Question 2

```java
import java.util.Optional;

public class Test2 {
    public static void main(String[] args) {

        Optional<Integer> inputNumber = 5;

        System.out.println(inputNumber / 0);
    }
}
```

### Answer

```text
Compilation error
```

### Why?

This line is invalid:

```java
Optional<Integer> inputNumber = 5;
```

An `int`/`Integer` value cannot be directly assigned to an `Optional<Integer>`.

Correct:

```java
Optional<Integer> inputNumber =
        Optional.of(5);
```

Also, even after fixing that line, this would still be invalid:

```java
inputNumber / 0
```

because `Optional<Integer>` is not an integer.

### Important interview technique

> Do not jump directly to the last line. First check whether the program compiles. If compilation fails, runtime exceptions are irrelevant.

# Output Question 3

```java
public class Test3b {
    public static void main(String[] args) {

        Integer inputNumber = null;

        System.out.println(inputNumber / 0);
    }
}
```

### Answer

```text
NullPointerException
```

### Why?

`inputNumber` is an `Integer` object:

```java
Integer inputNumber = null;
```

When Java evaluates:

```java
inputNumber / 0
```

it needs to convert/unbox the `Integer` to an `int`.

Conceptually:

```java
inputNumber.intValue() / 0
```

But `inputNumber` is `null`, so unboxing causes:

```text
NullPointerException
```

The division-by-zero exception is **not reached first**.

### Very important interview concept

```text
Integer
   ↓
unboxing
   ↓
int
   ↓
division
```

Since the reference is `null`, the program fails during unboxing.

# 🧠 Output Question Strategy

When the interviewer gives an output question, do NOT immediately calculate the output.

Use this order:

## Step 1 — Check compilation

Look for:

- Wrong assignment
- Missing imports
- Wrong method calls
- Type mismatch
- Access modifiers
- Invalid syntax

If compilation fails:

> **Answer: Compilation error**

Stop there.

---

## Step 2 — Check initialization

Ask:

- Is the value `null`?
- Is the object actually created?
- Is a variable initialized?

---

## Step 3 — Check evaluation order

Java evaluates expressions according to its rules.

For example:

```java
Integer number = null;

number / 0;
```

The `Integer` must first be unboxed.

So:

```text
null
 ↓
unboxing
 ↓
NullPointerException
```

The division by zero never gets a chance to happen.

---

## Step 4 — Check runtime exception

Common exceptions to recognize:

| Code situation | Likely exception |
|---|---|
| `Integer x = null; x + 1` | `NullPointerException` |
| `10 / 0` | `ArithmeticException` |
| `array[10]` when length is 5 | `ArrayIndexOutOfBoundsException` |
| `list.get(10)` when unavailable | `IndexOutOfBoundsException` |
| `Optional.of(null)` | `NullPointerException` |
| `Integer.parseInt("abc")` | `NumberFormatException` |
| Invalid cast | `ClassCastException` |
| Accessing `null` object member | `NullPointerException` |

```text
1. Definition
       ↓
2. Difference / How it works
       ↓
3. Practical example
       ↓
4. Real project use case
```

For output questions:

```text
1. Does it compile?
       ↓
2. What is initialized?
```
