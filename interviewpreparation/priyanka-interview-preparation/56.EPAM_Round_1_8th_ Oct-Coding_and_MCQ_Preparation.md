## 1. Coding: Values `4, 2, 7, 7, 9, 3` → Output `1, 0, 1, 0, 1, 0`

**Important:** The rule connecting the input values to this output is
not clear from the remembered example alone. The output alternates
between `1` and `0`, regardless of the values. If the task was simply to
generate an alternating sequence of the same length, Java code would be:

``` java
import java.util.Arrays;
import java.util.stream.IntStream;

public class AlternatingOutput {
    public static void main(String[] args) {
        int[] values = {4, 2, 7, 7, 9, 3};

        int[] result = IntStream.range(0, values.length)
                .map(i -> i % 2 == 0 ? 1 : 0)
                .toArray();

        System.out.println(Arrays.toString(result));
        // [1, 0, 1, 0, 1, 0]
    }
}
```

**Explanation:** `i % 2 == 0` is true for indexes `0, 2, 4`, so those
positions get `1`; the other positions get `0`. This answer is correct
only if alternating output was the intended rule. If the original
question described a property of each number, the full rule is needed.

## 2. Java Streams: Filter valid integers from a list of strings

**Question:** Given a list of strings, filter out values that are not
valid integers and return the valid values as a `List<Integer>`.

**Example input:**

``` text
["123", "32", "2as"]
```

**Expected output:**

``` text
[123, 32]
```

### Answer using Java Streams

``` java
import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;

public class ValidIntegers {
    public static void main(String[] args) {
        List<String> values = Arrays.asList("123", "32", "2as");

        List<Integer> result = values.stream()
                .filter(s -> s != null && s.matches("-?\\d+"))
                .map(Integer::parseInt)
                .collect(Collectors.toList());

        System.out.println(result); // [123, 32]
    }
}
```

**How it works:** 1. `stream()` processes the list. 2. `filter(...)`
keeps strings that contain an optional minus sign followed by digits
only. 3. `map(Integer::parseInt)` converts each valid string to an
integer. 4. `collect(Collectors.toList())` collects the integers into a
list.

**Interview note:** This regex checks the format, but an extremely large
digit string may still overflow `Integer`. If the input can contain
values outside the `int` range, use `try/catch` around parsing or parse
as `Long` if appropriate.

### Alternative: robust parsing with `try/catch`

``` java
import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;

public class ValidIntegersSafe {
    public static void main(String[] args) {
        List<String> values = Arrays.asList("123", "32", "2as", "999999999999");

        List<Integer> result = values.stream()
                .filter(s -> s != null)
                .map(String::trim)
                .filter(s -> !s.isEmpty())
                .map(s -> {
                    try {
                        return Integer.valueOf(s);
                    } catch (NumberFormatException ex) {
                        return null;
                    }
                })
                .filter(value -> value != null)
                .collect(Collectors.toList());

        System.out.println(result); // [123, 32]
    }
}
```

This version excludes malformed strings and values outside the `Integer`
range.

## 3. MCQ: Encapsulation and validated updates

**Question:** A class must not allow its fields to be changed directly,
but it should allow validated updates. Which design best supports
encapsulation?

**Answer:** Make the fields `private` and expose public methods that
validate input before changing the fields.

``` java
public class Employee {
    private int age;

    public Employee(int age) {
        setAge(age);
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age < 18) {
            throw new IllegalArgumentException("Age must be at least 18");
        }
        this.age = age;
    }
}
```

**Why:** Private fields prevent direct external modification. A setter
or domain method controls changes and enforces the class's rules. For
immutable objects, use a constructor that validates the value and do not
provide a setter.

## 4. MCQ: What does `ConcurrentHashMap` provide?

**Answer:** A thread-safe map designed for concurrent access by multiple
threads.

-   Multiple threads can read and update it safely.
-   It generally scales better than synchronizing every operation on a
    single shared map lock.
-   It does **not** allow `null` keys or `null` values.
-   Individual operations such as `put` and `get` are thread-safe, but a
    sequence of separate operations is not automatically atomic. Use
    methods such as `computeIfAbsent` when an atomic compound update is
    required.

**Example:**

``` java
Map<String, Integer> counts = new ConcurrentHashMap<>();
counts.merge("apple", 1, Integer::sum);
```

This safely increments the count for `"apple"` as one map operation.

## 6. MCQ: Spring MVC REST controller return value

**Question:** A handler in Spring MVC annotated with `@RestController`
returns an ordinary object. How is the return value used by default?

**Answer:** Spring writes the returned object to the HTTP response body,
usually serializing it as JSON when an appropriate message converter
(such as Jackson) is configured and JSON is negotiated.

``` java
@RestController
@RequestMapping("/api")
public class CustomerController {

    @GetMapping("/customer")
    public Customer getCustomer() {
        return new Customer(1L, "Priya");
    }
}
```

In this example, Spring typically serializes the `Customer` object into
JSON in the response body. `@RestController` combines `@Controller` and
`@ResponseBody`.

**Contrast:** With a traditional `@Controller`, a returned string may be
interpreted as a view name unless `@ResponseBody` is used.

## 7. MCQ: The `equals()` / `hashCode()` contract

**Question:** What does the Java `equals()` / `hashCode()` contract
require?

**Answer:** - If two objects are equal according to `equals()`, they
**must** return the same `hashCode()`. - If two objects have the same
hash code, they do **not** have to be equal. - The hash code should
remain consistent while information used in equality comparisons remains
unchanged. - If you override `equals()`, you should normally override
`hashCode()` as well.

**Why it matters:** Hash-based collections such as `HashMap` and
`HashSet` use the hash code to find a bucket and `equals()` to
distinguish matching keys or elements within it.

``` java
import java.util.Objects;

class EmployeeKey {
    private final int id;

    EmployeeKey(int id) {
        this.id = id;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof EmployeeKey)) return false;
        EmployeeKey other = (EmployeeKey) obj;
        return id == other.id;
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}
```

## 8. SQL: One row per `customer_id`, with the number of distinct orders

**Question:** Return one row for each customer and count that customer's
distinct orders.

**Answer:**

``` sql
SELECT
    customer_id,
    COUNT(DISTINCT order_id) AS distinct_order_count
FROM orders
GROUP BY customer_id;
```

**Explanation:** - `GROUP BY customer_id` produces one result row per
customer. - `COUNT(DISTINCT order_id)` counts each non-`NULL` order ID
once per customer. - If the table stores multiple line items for the
same order, `DISTINCT` prevents that order from being counted more than
once.

**Example data:**

  customer_id   order_id
  ------------- ----------
  10            501
  10            501
  10            502
  20            601

**Result:**

  customer_id     distinct_order_count
  ------------- ----------------------
  10                                 2
  20                                 1

If the interviewer wants customers with zero orders included, use a
`customers` table with a `LEFT JOIN` to `orders`, then group by the
customer ID and count distinct order IDs.
